SESSION: GitHub renders STYLED on WebKit 610 / Snow Leopard 10.6
============================================================================

MILESTONE: github.com went from raw unstyled HTML (every CDN asset transferred
0 bytes) to FULLY STYLED and rendering. JS engine runs. The only thing blocking
full React interactivity now is ES2022 private class fields (see LIMITATION).

--- ROOT CAUSE (the decisive fix): phantom synthetic redirects ---
synthesizeRedirectResponseIfNecessary (Source/WebCore/platform/network/mac/
WebCoreURLResponse.mm) fabricated a 302 redirect for EVERY initial subresource
load. On 10.6, [connection currentRequest] is nil on the first load of a
subresource; [[nil URL] scheme] is nil; -[NSString isEqualToString:nil] is NO,
so the same-scheme short-circuit failed and a synthetic redirect was built.
Diagnostic logging showed "cur=(null)" 129 times per page load. Each phantom
redirect was then rejected by checkRedirectionCrossOriginAccessControl ->
every github.githubassets.com CSS/JS asset denied -> unstyled page.
FIX: `if (!currentRequest) return nil;` at the top of the function (commit 9e0f9186e1).

--- LIMITATION / NEXT MAJOR ITEM: ES2022 private class fields (#field / #method) ---
610.1.15's JSC has NO private-fields support. The lexer rejects '#'
(parser/Lexer.cpp:525, "Invalid character: '#'"); there is no #name tokenization,
no parser support for private declarations/access, and no PrivateName/PrivateBrand
runtime infrastructure. usePublicClassFields exists (runtime/OptionsList.h:509) but
there is NO usePrivateClassFields option. GitHub's react-core uses #private syntax ->
SyntaxError -> "ChunkLoadError: Loading chunk failed after 3 retries" -> React does
not boot. GitHub renders STYLED but React-driven interactivity won't run until this lands.

Implementing it is a full feature backport, NOT a flag:
  Phase 1: Lexer — tokenize #identifier into a PRIVATENAME token.
  Phase 2: Parser — private field/method/accessor declarations; private access
           expressions (this.#x, obj.#m()); per-class private-name scope; #x in obj brand check.
  Phase 3: Bytecode + interpreter — op_get_private_name / op_put_private_name /
           op_check_private_brand / op_set_private_brand; PrivateSymbol slots.
  Phase 4: Brand checks for private methods/accessors.
  (Defer DFG/FTL JIT — let the new ops run in the interpreter (LLInt) first.)
RECOMMENDED: validate in a jsc-shell harness on a minimal
  `class C { #x = 1; get() { return this.#x; } }` BEFORE re-testing in-browser.
  Never debug a new language feature through a full GitHub load. Multi-session effort.
